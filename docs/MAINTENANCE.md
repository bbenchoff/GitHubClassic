# Building, testing and maintenance

## Native build

Use CodeWarrior Pro 4 and its classic Mac SDK. Clone with Classic Github so
the project and interface files have their actual resource forks. Keep `SRC`
beside `Output`; keep `GHClient Login Helper` beside the application when
testing saved login.

The project uses recursive, project-relative access to `SRC` and writes to
`::Output:`. Build PPC Final MacOS Toolbox, 68K Final MacOS Toolbox, then FAT
MacOS Toolbox. The FAT target incorporates the 68K output. The final download
is `Output/Classic Github`.

On a fresh CodeWarrior installation, increase the IDE's preferred memory
allocation in Finder Get Info while it is closed. The 0.2 build used 64 MiB;
the default 5.5 MiB allocation could compile but failed at the full link.
Script Editor needed a larger allocation for source-transfer scripts too.
These are development-tool allocations, separate from the application heap.

Preserve the MacRoman/CR text format in existing native C and header files.
Modern Python tools, tests and Markdown use UTF-8. Do not bulk-normalize the
source tree or replace resource-only files with empty ordinary files.

## Portable regression suite

Requirements: Python 3.10+, a GCC-compatible C compiler with LTO, and Git
2.29+. On Unix, install the compiler's 32-bit C library development support;
the port requires a 32-bit `long` and the runner uses `-m32`. On Windows,
MinGW-w64 uses a 32-bit `long` even with a 64-bit compiler.

```
python tools/run_tests.py
python tools/run_tests.py --cc C:\msys64\mingw64\bin\gcc.exe
```

The runner builds in a temporary directory and invokes independent Git locally.
It sends no requests to GitHub and uses synthetic credentials only. It checks:

* TLS Finished known answers against Python HMAC, plus actual allocation
  failures and propagation through the production send/receive paths.
* Plain-file Finder defaults, legacy baselines and checkout/restore plans.
* MacRoman metadata against Python's codec, including every printable high byte.
* New-vault passphrase boundaries and an independently encrypted legacy fixture.
* Incremental and full pack construction, cancellation, corrupt/missing base
  data, size bounds and equivalence of buffered/disk writers.
* Git acceptance of the incremental pack in a repository seeded only with its
  old history, with exact object-set comparison and `git fsck`.
* Companion-file workflows, overwrite protections, symlink refusal and generators.

The native port's integer compatibility headers are adapted for these host
checks. They do not test Toolbox pointer ABI, native I/O, window behavior,
operator entropy quality or physical-machine timing.

Regenerating the synthetic vault fixture additionally requires Python's
`cryptography` package. Normal regression runs do not need it:

```
python tools/make_test_vectors.py --check
```

## Generated build inputs

```
python tools/menu_catalog.py --check
python tools/make_trust_roots.py --check
```

Remove `--check` to regenerate the corresponding header. Menu command numbers
come from `tools/menu_catalog.tsv`; edit the native MENU resources alongside
catalog changes. The generator does not edit those resources.

Public PEM inputs and DER SHA-256 fingerprints are in `tools/trust-roots`.
The root generator performs no download and makes no trust decision. Updating
a root requires independent review of its origin, fingerprint, validity and
intended trust, followed by native HTTPS tests. Matching generated bytes is
not proof that a CA remains trustworthy.

## Native merge fixtures

Install `machfs==1.3` in the modern Python environment. Create a new detached
image; existing images and manifests are refused:

```
python tools/make_merge_fixtures.py merge-test.hfs
```

The generator checks object identities and expected commits with independent
Git, then writes a 16 MiB HFS volume named GH Merge. It contains separate sets
for PPC, 68K and FAT. Attach it read/write to the test Macintosh. Launch one of
`MacOS Toolbox PPC`, `MacOS Toolbox 68K` or `Classic Github`, then choose
Help > Test Merge Checkout. Each slice can run once on its own fresh set.

After the runs, use Finder **Put Away** on the volume, then detach it from the
emulator. Eject alone can leave a logical disk behind. Never read or rewrite
the host image while the guest owns it. Check the closed image:

```
python tools/check_merge_results.py merge-test.hfs merge-test.json --slice PPC
python tools/check_merge_results.py merge-test.hfs merge-test.json --slice 68K
python tools/check_merge_results.py merge-test.hfs merge-test.json --slice FAT
```

The checker compares refs, index trees, original object identities, both
working forks and normalized Finder information, then imports the native
objects into Git for strict verification. Its HFS reader checks B-tree index
and leaf agreement; it is not a general HFS allocation/repair utility.

These fixtures exercise merge, fast-forward, forced merge, conflict refusal,
stale-state refusal and already-current behavior. They do not simulate a
physical power interruption or test every saved-session recovery path.

## Modern-host file renames and deletions

Ordinary Git does not understand the path embedded in a Macintosh companion.
For a single regular file, update it after the data-fork operation:

```
git mv Foo.c Bar.c
python tools/mac_forks.py rename Foo.c Bar.c
git add -A .ghclient-mac
python tools/mac_forks.py validate --cached
```

```
git rm Bar.c
python tools/mac_forks.py remove Bar.c
git add -A .ghclient-mac
python tools/mac_forks.py validate --cached
```

The helper preserves the complete AppleDouble payload on rename and refuses
to replace a destination record. Source companions must match the Git index;
preserve or stage resource edits before proceeding. It does not stage changes,
change data forks, infer renames or repair directory moves. Use a case-sensitive
modern checkout for case-only renames. Native operations remain fork-aware.

`validate` checks working-tree records; `validate --cached` checks the staged
snapshot that will be committed. Run both before contributing cross-platform
file maintenance. The helper requires regular paths without symlinks/reparse
points and a filesystem supporting hard links for atomic new-record creation.

If interrupted after publishing a renamed record but before retiring its
source, both records may remain. Preserve them, compare their embedded paths
and fork payloads, and restore the appropriate record from Git before retrying.
The helper never treats an unfamiliar extra record as safe to delete.

## Space and performance

Routine fast-forward pushes send new objects only. Shared history is still
read and verified locally; first pushes and force-with-lease pushes send a
complete reachable pack. Stored DEFLATE blocks remain uncompressed and have
no delta encoding. Fetch/clone buffering and the documented object limits are
unchanged.

Completed checkout backups and loose objects are retained. There is no
automatic backup pruning, repacking or garbage collection in 0.2. Do not delete
`checkout-native`, journals, intents, locks, stash or rebase state as a cleanup
shortcut. An old backup can still be relevant to a saved operation.

The supported space-reclamation approach is a separate fresh clone after
pushing required branches and preserving untracked files, local-only commits,
stashes and saved work. Keep the old repository until the replacement and
those saved items have been checked. The custom local `.git` layout cannot
be maintained with command-line `git gc`.

## Release evidence

The 0.2 portable runs on Windows/MinGW and 32-bit Linux passed 853 C checks
and nine Python maintenance tests. Its Git interoperability fixture reduced a 1,318,796-byte
complete pack to 1,742 bytes containing exactly 15 missing objects. This is a
fixture measurement, not a physical-network benchmark.

Native release validation uses QEMU's PowerPC Macintosh with Mac OS 9.2.2.
PowerPC, 68K and FAT executables are compiled with CodeWarrior. Running the
68K executable there exercises the operating system's 68K emulation, not a
physical 68040. Physical hardware/System 7.5.3 qualification, entropy quality,
power-loss recovery and large-repository timings remain separate work.

The 0.2 QEMU run passed all six native merge cases in each of the PowerPC,
68K and FAT executables. Detached-image checks confirmed the expected refs,
index trees, original objects, data/resource forks and normalized Finder bytes
for all 18 cases. Saved GitHub authorization refreshed successfully in all
three executables. Two native Toolbox commits verified accented identities
and messages as UTF-8 while retaining the original MacRoman file data.
